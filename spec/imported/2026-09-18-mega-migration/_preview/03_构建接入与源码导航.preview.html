4. 构建链迁移清单

历史 xllm-ops 链：根 build 脚本 → xllm_ops/build_aclnn.sh → 内层 build.sh/CMake → Host opapi/proto/tiling + Device 编译 → CANN OPP 包。历史分析提到芯片专用算子列表和 .done 复用风险；本地须检查当轮文件，不能把目录存在等同于参与构建。[H]

vllm-ascend 以 setup.py、顶层/CANN CMake、csrc/build_aclnn.sh 和扩展链接共同形成安装链。逐项完成：

  1. 将 Mega 加入 910B 实际选中的 ACLNN 算子列表；确认单算子选择和完整 editable build 都包含它。

  2. 完整迁入 Host/Device 与目录 CMake；确认 proto/infershape 与新增 ABI 一致。

  3. 为该算子配置 PTO include/宏/编译选项。限制配置作用域，避免改变其他算子。

  4. 对齐 Host tiling data 与 Device 解包定义，包括字段宽度/顺序；更改 ABI 后两端同步。

  5. 生成 ACLNN API，并使 C++ adapter 编译链接到正确名称。拟新增命名先与父仓现有符号检索去重，避免两 vendor 下同名旧 ABI 被误加载。

  6. 打包到父仓既有自定义 OPP 路径；保留其环境引导机制。不得要求额外安装 xLLM 服务或手工覆盖全局 vendor 包。

  7. 检查实际 Python _C_ascend 扩展、OPP vendor 和 tiling/kernel 产物来自同轮。符号加载后做真实 smoke，不能只 hasattr。

  8. 校验未启用 Mega 时原生路径仍能运行；缺少新包要在状态写入前明确回退或在强制测试模式报错。

原版 AddConfig("ascend910b") 是支持声明。Host 通用路径 UB reserve 为 175,360B；A2/A3 使用 mixed AIC/AIV 调度，A5 有不同分支。修改 tiling/参数缓冲后重新核算 UB 与同步资源，不能照抄旧阈值而不检查。[V/T]

原版 non-FLA 有专用 key 偏移，且没有启用全部 FLA group-cache/deferred-norm 特化。910B + non-FLA 首版先稳定正确，不迁入仅 A5 的优化以追求纸面收益。

5. 服务器构建命令骨架

这些是前期基线的命令模式，不是已经在用户服务器验证过的脚本。本地 Codex 应从当轮 README/setup/build 脚本生成准确的 remote_run 操作说明，含工作目录与阶段。

# 服务器：位于精确候选 commit 的 vllm-ascend 根目录。
# ACTUAL_SOC 由服务器实际设备确定；如完整 SoC 名称 ascend910b1。
export SOC_VERSION="$ACTUAL_SOC"
export COMPILE_CUSTOM_KERNELS=1
python -m pip install -v -e . --no-build-isolation

仅在当轮 csrc/build.sh 支持该参数与位置时，用以下单算子模式定位构建错误：

# 服务器工作目录：vllm-ascend/csrc
bash build.sh --pkg --ops=mega_gdn_mtp_decode --soc=ascend910b -j8

单算子 build 不替代最终父仓 editable 安装与真实加载检查。不要误把 Python editable 当作 C++/设备二进制即时更新；修改原生代码后必须重新构建。安装时如依赖解析可能替换 vllm/torch_npu，记录实际包版本，并确认 vllm import 来自所要求的源码版本。

构建失败时回传最早 error 前后完整上下文、实际编译命令、CMake cache 中相关定义和产物路径；不要只回传最后一行 make failed。需要清理增量产物时限定到已识别的本项目 build 目录，先记录路径；不要求盲目清理全局 CANN 或其他项目。

6. 模型接入：融合范围要从 core 扩展至 norm

本次复核的调用链：[V]

AscendGatedDeltaNetAttention.forward
  → 输入投影、QKV/Z/B/A 排列
  → torch.ops.vllm.qwen_gdn_attention_core
  → _forward_core
      → causal_conv1d_custom
      → fused_gdn_gating + Q/K L2Norm
      → npu_recurrent_gated_delta_rule
  → self.norm(core_attn_out, z)
  → out_proj

必须保留：

  • 投影与 TP 后布局，包括非 interleaved/interleaved 分支及各 rank 的头数。

  • wait_for_kv_layer_from_connector、attention compute fence、相关保存/传输钩子的语义与执行位置。

  • profile/dummy-run 缺 metadata 的行为；warmup 不得用伪 metadata 写入真实请求 cache。

  • core 输出初始化/有效 token 区域约定及调用者的 output buffer 更新方式。

建议新增一个 Ascend 内部“core+norm”边界，两个分支都给出已 norm 输出。不要让外围调用者猜测输出是否归一化。不要直接改变所有后端共享的 qwen_gdn_attention_core 全局契约；先找本仓允许的独立 wrapper/注册扩展点。

首版混合批次整体回退最容易验证。后续若在一批内 Mega 处理 spec、原生处理 non-spec，必须对各子集分别且仅一次执行 norm，再按原 token index 合并；性能报告同时计入 gather/scatter。此项不是首版正确性的前提。

7. PyTorch/图模式审查

  • schema 中准确标识 cache/output 的 mutation 与 alias；不要把有副作用算子伪装为纯函数。

  • 若 cache 藏在 layer/context 中，明确所用编译后端如何保持其副作用；必要时将其显式传入边界。

  • Fake/Meta 只依赖 shape、dtype、stride 等元信息，不能读真实数据或更新 cache。

  • 首次 capability smoke 使用隔离状态并放在启动/warmup阶段；不在请求现场触发会修改真实状态的探测。

  • graph capture 前完成权重转置/contiguous、必要 buffer 分配；replay 更新稳定 metadata buffer。

  • 图捕获、Dynamo 编译、TorchAir/ACLGraph 等不同模式分别核对；只实现 Fake 不等于设备图已可回放。
