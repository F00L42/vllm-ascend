# 主开发计划：MegaGdnMtpDecode 迁移至 vLLM-Ascend / Ascend 910B

日期：2026-09-18；先读 [00\_README.md](00_README.md) 的证据口径与约束。

## 1. 决策与目标

**推荐采用“保留 vLLM 状态体系 + 改造 Mega 访问接口”的路线。** 复用其 Conv、Q/K 归一化、门控、GDN 递推与 RMSNorm/Z gate 的设备内融合结构；由 vLLM 继续决定请求排序、物理状态块、接纳后的有效前缀、缓存发布和回收。[D]

目标是减少目标模型 GDN 多 token 校验段的框架下发和小算子间开销。不是迁移整个 xLLM 引擎，也不是把一个 recurrent 函数名替换为 Mega。前期结论认为有移植基础；**910B 编译可行、状态正确、实际加速**是三个分别验证的命题，当前均无本项目实机结果。[H/T]

首个可验收版本：目标模型中符合约束的 GDN 层，在纯投机校验、等长 S、eager、无共享 prefix 写入的受控路径上，使用适配后的 Mega；其他输入在任何状态写入之前走原有路径。初期验收范围窄，最终覆盖范围逐项扩展。

## 2. 开发约束变成工程要求

| 用户约束 | 落地要求 |
| --- | --- |
| Codex 只能本地读改源码 | 本地做调用链核对、CPU 契约模型、静态审查；NPU 结果一律标记 pending |
| 四仓 main 每天更新 | 每轮记录 parent/submodule 完整 SHA、工作树状态和影响分析；按组合复现 |
| 服务器拉个人 vllm-ascend 分支 | 实现优先落在父仓；仅改 submodule 指针不能传递未发布的子仓修改 |
| 服务器编译 + editable 安装 | 实验记录实际 Python import 路径、动态库/OPP 路径、产物 hash，防止测到旧包 |
| 只能拿回运行结果 | 每轮预先定义“假设、测试、telemetry、回传文件、下一步分支”，一次解决一个明确问题 |
| 可在源码打印/dump | 默认关闭；定向捕获；诊断和性能运行分开，避免引入 D2H 同步污染结论 |

## 3. 前期结论与适用边界

| 结论 | 状态 | 开发含义 |
| --- | --- | --- |
| Mega 融合 Conv4/SiLU → QK L2Norm → gate/decay → recurrent/checkpoint → RMSNorm/Z gate | V | 融合调用必须覆盖 core 和 norm |
| 原版 OpDef 注册 `ascend910b` | V | 有移植依据，不能据此声称 910B 已实测 |
| 原版用连续 slot×S；vLLM 从 block table 生成 checkpoint 索引 | V | 改寻址，不重建第二套长期状态池 |
| vLLM SSM 按 `[NV,Dv,Dk]` 使用 | V | 优先 non-FLA，继续核对真实 stride |
| xLLM 模型当时仍走拆分链，Mega 未实际接入该模型调用链 | H | 本地以 `rg` 重查，不能将 xLLM 服务当已验证模板 |
| 原版 `g` 经 BF16 物化，Ascend gating `g` 为 FP32 | V | 数值等价是独立任务；可能需要修改融合计算的舍入点 |
| prefix、异步调度、graph、混合批次涉及额外状态生命周期 | H/V | 分阶段放行，不能一次全部启用 |

原版限制包括 BF16 激活、FP32 SSM、Dk=Dv=128、Conv 宽度 4、B≤32、2≤S≤17、NK 为不大于 16 的 2 次幂、NV/NK 为 1–4 的整数、N≤1024。以 TP 后每 rank 的实际 shape 判断，不以模型名称判断。N 是原版 slot 数，**不得直接改写为 vLLM 物理 block 上限**。[V]

## 4. 推荐接入架构

```text
flowchart TD
    A["投影与现有元数据"] --> B{"调用前资格判定"}
    B -->|支持| C["Mega core + norm 适配调用"]
    B -->|不支持| D["原有 core + norm"]
    E["vLLM 状态池与物理映射"] --> C
    E --> D
    C --> F["统一的归一化后输出"]
    D --> F
    F --> G["输出投影"]
    C --> H["现有接纳后处理与缓存生命周期"]
    D --> H
```

建议把外部可见语义统一为“返回 norm 后的 GDN 输出”。否则 Mega 分支返回已归一化值、fallback 返回未归一化值，会把分支语义泄漏到外层并增加重复 norm 风险。具体 custom op 边界遵循当轮编译后端，保留已有 connector 等待、状态搬移依赖及保存钩子。[D]

资格判定分两类：shape/dtype/配置等静态条件由 host 检查；活跃行、动态索引和游标通过已有设备 metadata 或适配后的设备逻辑处理。不要在每层对设备张量 `.item()`/`.cpu()` 后决定分支。首版不支持的动态批次，使用调度侧已有 CPU 描述在调用前整批回退。

不推荐每层每步将完整 vLLM cache gather 为 Mega 连续池再 scatter 回去。临时 staging 可用于隔离验证，但必须标为测试桥接，且其搬运成本不能隐藏在加速报告外。

## 5. 分阶段计划与退出条件

阶段允许拆成多个远端轮次；“本地写完”不等于通过阶段。共享证据规范见 [04](04_服务器验证与Telemetry.md)。

| 阶段 | 本地 Codex 工作 | 服务器执行 | 退出条件 |
| --- | --- | --- | --- |
| P0 基线与契约 | 建四仓 manifest；解析真实调用分支、metadata 生产者/消费者；补契约表；写默认关闭的基线采集 | 原生链单层/短序列运行；回传 shape/stride、游标、checkpoint 映射和环境 | 能解释一轮校验及下一轮的每个状态读写；冻结数值基准与首版 shape |
| P1 构建最小闭环 | 移入 OpDef/proto/tiling/kernel、PTO 配置、binding；先不接模型；保留独立参考 | 编译、安装、符号加载；原版布局的最小算子 smoke | 910B 正确 kernel 被调用；有完整日志和最小数值输出，原生路径仍可运行 |
| P2 vLLM 状态 ABI | 增加物理索引、独立 Conv 位置、真实 stride；non-FLA；明确 mutation | 非连续块/页 padding/原位/共享只读/非法写集合测试；逐 checkpoint 比较 | 输出、SSM、Conv、未触及块全部满足契约；无新增逐层 D2H |
| P3 最小模型路径 | core+norm 接入；资格判定和路由证据；解决数值差异 | eager、纯 spec、固定 S、B=1 后 B>1；跨轮拒绝/全接纳回放与短 E2E | 真正命中 Mega，norm 恰好一次；下一轮状态对齐；fallback 在写入前完成 |
| P4 调度和缓存 | 覆盖 batch 重排、请求回收、postprocess 游标重置、prefix/COW、异步依赖；逐特性开启 | 多轮、prefix hit/miss、抢占恢复、混合批次；启用的 async 配置单独跑 | 已声明支持的生命周期全部正确；未支持配置明确回退 |
| P5 图模式 | 稳定地址、Fake/Meta、mutation、capture/replay、padding；持久 metadata 更新 | eager 对图模式；连续 replay、改变活跃行/索引/accepted、spec→no-spec→spec | 图不使用旧 metadata、不污染无效行；无 graph break 或意外重捕获 |
| P6 性能与收敛 | 优化 metadata/布局转换；汇总命中率与限制；移除临时默认日志 | telemetry 关闭的 A/B；kernel、层调用、服务三层测量 | 正确性不退化，目标工作负载有可复现净收益；给出范围和回退说明 |

P1 的原版 ABI 仅用于编译/计算冒烟，不要求为它建设生产长期状态池。若构建和 ABI 修改已经可独立审查，可以合并代码交付，但服务器仍分别记录两个门槛。P4 与 P5 的测试组织可交叉，生产启用必须满足相应组合。

## 6. 每阶段应留下的代码与资料

- **P0**：`source_manifest`、实际调用链表、状态边界样例、数值差异表、首轮测试说明。
- **P1**：构建变更、来源和许可证说明、低层 binding、最小 NPU 算子测试；功能默认关闭。
- **P2**：适配 ABI 文档、CPU 地址/生命周期 reference、物理池随机排列与 sentinel 测试。
- **P3**：模型路由、原生 fallback、双状态副本比较 harness、跨轮回放用例。
- **P4/P5**：按特性更新支持矩阵；每个模式提供运行证据，不用一个 eager PASS 覆盖 graph/async。
- **P6**：同环境 A/B 原始结果、命中率/回退原因、最终维护说明和下一次 rebase 关注点。

测试/目录名由当轮仓库习惯确定。不要把本包里的建议名称当已存在文件。

## 7. 性能收益假设

| 可能减少的成本 | 条件与边界 |
| --- | --- |
| Conv、gating、Q/K norm、recurrent、norm/gate 的多次 Python/dispatcher/ACLNN 下发 | 原生路径确实分开下发，且候选没有新引入同量 metadata 小算子 |
| 独立门控和归一化中间值物化、部分 state 反复读取 | Mega 仍有 `convOut` GM 物化、跨 owner 同步和逐 token checkpoint 写回，不能说完全消除 HBM 往返 |
| 小 kernel 之间的调度间隙与同步开销 | 需从 trace 识别关键路径；不是所有间隙都由 CPU 下发导致 |
| 重复布局处理/临时分配 | 只有 adapter 使用原生布局、预准备权重且避免整池搬运时才成立 |

不包含：投影 GEMM、out\_proj、其他 attention/MLP/MoE、TP 通信、草稿模型、采样/拒绝采样、scheduler、请求输出及网络。接纳后的 cache 整理也不会因融合 GDN 自然消失。

使用实测分解：`T候选层 = T准备与适配 + TMega + T必要后处理`；`净收益 = T原生层 − T候选层`。服务理想上限可用 `1 / ((1-f)+f/r)` 检查，其中 f 为可替换段占服务关键路径比例，r 为该段实际加速倍数。此式是解释工具，不是性能承诺。910B + non-FLA 的收益不能从 950/A5 或 FLA 特化外推。

## 8. 停止、缩范围与回退规则

1. **构建不通**：只处理最早失败的 PTO/编译/链接/包发现层，不继续叠加模型变更。
2. **状态映射不明**：先用原生 trace 和 CPU 回放补足，不能用 clamp 索引或扩大容差绕过。
3. **数值不同**：先找首个分歧阶段，明确目标是遵循 vLLM 数值还是经过批准的新近似；本计划默认前者。
4. **候选 launch 后异常**：不在同一已污染状态上直接运行 fallback。停止该验证，使用受控快照重建请求/重启进程后再测。
5. **性能无收益**：分解适配、kernel、state 写回和命中率；可以保留默认关闭实验路径，不能仅报微基准最好值。
6. **main 已覆盖功能**：对比上游新实现，减少重复补丁；不机械恢复旧实现。

## 9. 完成定义
