## 使用约束

- 本地只有 vllm-ascend 与作为 submodule 的 vllm、xllm、xllm-ops 源码，以每日更新的 main 为基线开发个人分支。
- 本地 Codex 无服务器/NPU 访问能力；不得把服务器执行写成本地已完成步骤。
- 服务器拉取个人分支及精确 submodule 提交，编译算子，editable 安装源码，再运行 UT/E2E。
- 需要更多证据时，在源码中增加默认关闭的 telemetry/dump，由服务器执行者回传。
- 历史 commit 用于理解前期分析；实施以当轮本地 main 为准。每轮冻结一个四仓 SHA 组合，服务器不得各自追最新 main。

## 证据标签

- **[H] 历史分析**：来自本项目 2026-09-16/17 分析，不代表今日 main。
- **[V] 本次复核**：本次读取了指定历史 commit 的源码/文档；仍是静态证据。
- **[D] 设计建议**：本资料包提出的迁移接口、阶段和测试，不是已有 API。
- **[T] 待服务器验证**：编译、实际分发、数值、状态及性能均需执行证据。

本次复核重点：`xllm-ops@fee381637f07` 与 `vllm-ascend@7a0aaebca691`。两者为前期基线的短 SHA，不是本轮开发锁定版本。没有运行 CANN 编译、910B UT、图回放或端到端性能测试。

## 三条最容易误用的结论

1. Mega 的 `numAcceptedTokens` 文档口径不能直接套到 vLLM 的 `num_accepted_tokens`；后者在状态整理后可能重置为 1。必须按“当前状态代表哪个已计算前缀”核对。
2. `flaSsmStateLayout=false` 解决矩阵方向，不解决物理 block 跳转、页间 stride、Conv 历史窗口和所有权问题。
3. 原版 Mega 对 `g` 做 BF16 舍入，本次复核的 Ascend gating 输出 `g` 为 FP32。迁移必须建立 vLLM 数值基准，不能以“xllm 单测通过”代替 vLLM 等价验证。

所有建议的开关、ABI 字段、测试名和目录均显式标注为拟新增项。本包是开发资料，不包含已实现的迁移补丁或可直接运行的 NPU 测试程序。
