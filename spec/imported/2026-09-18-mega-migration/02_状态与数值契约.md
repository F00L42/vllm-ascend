# 参考：状态、数值与融合边界契约

日期：2026-09-18。此文件是 adapter、tiling 和 kernel 修改的主要审查依据。  
证据标签见 [00](00_README.md)；源码入口与链接见 [03](03_构建接入与源码导航.md)。

## 1. 必须分开的三个问题

1. **计算语义**：给定同一段 QKV、门控参数及初始状态，计算何种输出与后续状态？
2. **存储语义**：逻辑状态对应哪个物理 block、哪个历史偏移和哪个 stride？
3. **生命周期**：此状态属于谁、代表哪个已计算前缀、何时允许写入/发布/复用？

复用 Mega 主要解决第一项的融合结构，仍需核对数值细节；第二、三项服从 vLLM。相同 shape 不意味着相同契约。

## 2. 原版 Mega ABI：用于识别差异，不是直接接入规格

以下据 `xllm-ops@fee381637f07` 的算子文档与 Host 源码。[V]

记 B 为请求行数，K 为草稿 token 数，S=K+1，D=128，NK/NV 为当前 rank 的 key/value heads，C=(2NK+NV)D，L=S+2，N 为原版逻辑 slot 数。

| 参数 | dtype / shape | 语义 |
| --- | --- | --- |
| qkv | BF16 `[B,S,C]` | Conv 前的 QKV |
| z | BF16 `[B,S,NV,D]` | 最后输出 gate |
| b / a | BF16 `[B,S,NV]` | beta / decay 输入，勿互换 |
| convWeight | BF16 `[4,C]` | 无额外 bias 参数的 Conv 权重 |
| convState / convStateOut | BF16 `[N,S+2,C]` | 原始 QKV 历史及本轮写回 |
| aLog / dtBias | FP32 `[NV]` | 衰减参数 |
| ssmState / ssmStateOut | FP32 `[N*S,NV,D,D]` | 每 token checkpoint |
| readStateIndices / writeStateIndices | INT32 `[B]` | 逻辑 slot，不是任意物理 checkpoint ID |
| numAcceptedTokens | INT32 `[B]`，1…S | 原版用于选择上轮 checkpoint 的游标 |
| normWeight | BF16 `[D]` | RMSNorm 权重 |
| flaSsmStateLayout | bool | true 保存 `[K,V]`，false 保存 `[V,K]` |
| convOut | BF16 `[B,S,C]` | 中间 Conv 物化结果 |
| out | BF16 `[B,S,NV,D]` | 已完成 RMSNorm 与 Z gate |

原版要求 ND contiguous；首版支持范围为 B=1…32、S=2…17、NK∈{1,2,4,8,16}、NV/NK∈{1,2,3,4}、N=1…1024、Conv4、D=128。S=1 不是这个 MTP 算子的原版有效输入。

原版索引规则，对行 b 设 r=read slot、w=write slot、m=numAcceptedTokens：

```text
SSM 读：r*S + m - 1
SSM 写：w*S + t，t=0…S-1
Conv 初始 3 行：read[r, m-1:m+2, :]
Conv 写前 2 行：write[w, 0:2, :] = read[r, m:m+2, :]
Conv 写后 S 行：write[w, 2:S+2, :] = qkv[b, 0:S, :]
```

Conv 保存的是原始 qkv，不是卷积后激活。输入/输出池可以分离；独立输出池的其他未写 slot **不保证已有内容**。若需要保留整个池，调用侧必须正确初始化/保留未写区域。生产适配应直接写请求拥有的状态区域，而不是用未初始化的新整池替换旧池。

原版文档称 accepted “包含 correction token”。这只定义其文档场景下的计数约定，不证明 vLLM 同名字段的来源、时点和重定位后语义相同。

## 3. 与 vLLM 的关键差异

| 项目 | 原版 Mega | vLLM-Ascend 基线及迁移要求 |
| --- | --- | --- |
| token 排列 | 固定 `[B,S,…]` | 投影常为 packed `[T,…]`；spec/non-spec 分组和 token index 必须逐一对应 |
| SSM 寻址 | slot×S+t | 从 metadata/block table 获得物理 checkpoint；不保证相邻 |
| SSM 矩阵方向 | 默认 `[K,V]` | 基线使用 `[V,K]`；优先 non-FLA |
| SSM block 间距 | 连续矩阵积 | 以真实 cache view/分配器 stride 为准；不能从 shape 乘积推定 |
| Conv 状态定位 | slot 和 m 决定窗口 | Conv 取对应 cache 行/首 block，历史偏移由有效游标决定；不等同于 SSM checkpoint block |
| accepted | 原版 slot 内 checkpoint 游标 | 会受 postprocess/重定位影响；不能沿用原始采样数 |
| qkv/gate/norm | 固定 dtype 和舍入 | 以实际 Ascend 原生链数值基准为准 |
| padding | 原版无 PAD\_SLOT 跳过契约 | vLLM 可能传负哨兵或零长行；需要显式跳过协议或合法 sink |
| 生命周期 | 调用者提供读写 slot 所有权 | 请求、共享 prefix、COW、抢占、状态复制由框架管理 |
| norm 边界 | 已在 Mega 内 | 原路径 norm 位于 core 之后，接入时必须去重 |

注意：本次看到的 recurrent 内核会按 `seq0 + accepted - 1` 读取展开后的索引表。在固定 S 情况下可理解为 `table[b, accepted-1]`，但变长时不能未经验证就把一张固定宽二维表 flatten 后使用；必须一起审计 `actual_seq_lengths`、行宽和有效 token 排列。

基线 `gdn_attn_builder.py` 的 `_build_actual_seq_lengths` 生成“起始偏移 + 每请求长度”编码，不是一般意义的纯长度数组，也不是普通 cumulative offsets。原生 helper 作为独立接口核对，不按参数名猜测。Mega 固定 S 首版可避开该转换；支持变长时必须明确转换规则。[V]

## 4. 状态游标不等于采样接受数

用语义边界判断状态：`state(prefix)` 表示目标 GDN 已消费该前缀所有输入 token 后的状态。采样刚产生的 token 尚未经过下一次 forward，不自动出现在 recurrent state 中。

固定步长示例，K=3，本轮目标输入为 `[u0,d1,d2,d3]`，u0 是上一轮输出、此次首次进入目标 forward 的输入；d1…d3 是草稿候选。检查点 0…3 分别是消费这些位置后的状态。

| 校验结果 | 保留的已计算状态 | 下一轮首先消费 | 未重定位时可对应的游标 |
| --- | --- | --- | --- |
| d1 即拒绝 | checkpoint 0：仅消费 u0 | 新采样 correction c | m=1 |
| 接纳 d1，拒绝 d2 | checkpoint 1：消费 u0,d1 | correction c | m=2 |
| 接纳全部 3 个草稿 | checkpoint 3：消费 u0,d1,d2,d3 | 新采样 bonus c | m=4 |

此例说明 m 可为“已接纳草稿数+1”；**它不是通用赋值公式**。若框架把所需状态复制到新的基准位置，后续 m 可能变成 1；重新使用采样时的 m 会再次偏移。

本次复核 `postprocess.py`：它按 Conv/temporal state 分别复制，在 `src_block_idx == dest_block_idx` 且指定 state/tile 条件下将 accepted 输出重置为 1。不是所有复制都无条件重置。[V]

当轮本地必须追完：采样输出 → runner 更新 → postprocess/precopy → 请求重排 → metadata builder → Conv/recurrent 消费。记录每个阶段的“请求标识、迭代、已计算 token 边界、游标、物理 ID”。异步调度不能假定 CPU 最新字段就是此次设备 kernel 要消费的那一版。

## 5. 建议的 vLLM 专用 ABI

以下全部为 **[D] 拟议接口字段，不是已存在 API**。实际 schema 在 P0/P2 基于源码定稿。

| 字段/信息 | 目的 | 实现原则 |
| --- | --- | --- |
| qkv,z,a,b + 静态维度 | 计算输入 | 首版固定 S 且 dense，保证对应同一请求与 token 顺序 |
| conv read/write block IDs | 独立 Conv 定位 | 可由同一框架池产生；独占请求允许合法原位，共享 prefix 不可原位写 |
| conv history offset | 已确认历史窗口起点 | 使用框架整理后的游标，不从采样数二次推导 |
| ssm checkpoint table + read cursor，或显式 read/write IDs | SSM 物理寻址 | 二选一形成单一权威来源，避免维护两套可能不一致的映射 |
| state block/head/inner strides | 真正地址计算 | 元素或字节单位写入 ABI；offset 乘法先转 64 位 |
| conv 时间/通道 stride | Conv SD/DS 或 view | 首版只支持已验证布局，不支持则调用前回退 |
| active rows / valid lengths | padding / 变长 | 只有确需支持时增加；设备跳过协议不能破坏全核同步 |
| out / convOut / mutable state | 输出与副作用 | 输出和 cache mutation 在 dispatcher、Fake 和图后端中一致声明 |
| numerical configuration | eps、scale、激活和精度 | 首版严格匹配已核对配置，其他配置回退 |

建议首版 SSM 采用“当前 vLLM checkpoint 表 + 有效游标 + 显式 stride”设计，减少额外 gather 小算子。如果共享读/独占写不能由原表表达，则增加独立读写表，仍由 vLLM 生命周期提供，不由 kernel 私自分配。

抽象地址公式：

```text
read_id = checkpoint_table[b, effective_cursor[b]-1]
write_id(t) = write_checkpoint_table[b,t]
ssm_addr = base + id*block_stride + h*head_stride + v*v_stride + k*k_stride
conv_addr = conv_base + conv_id*conv_block_stride
            + history_index*time_stride + channel*channel_stride
```

公式中的 table、cursor 必须是当次 forward 所需的版本。两种 state 可有不同基地址、池大小和组别，不能共用一个通用 `state_id*S`。本次复核的 postprocess 支持多 mamba group 与 request-slot/batch-slot 映射；适配层也不能默认所有组使用同一张表。[V]

额外要求：页内非连续 view 不能通过对 mutable cache `.contiguous()` 悄悄变成副本；否则 kernel 更新的是副本。若首版仅接受某种 stride，资格判定拒绝其他布局。改变 Host ND/contiguous 要求时，proto/tiling、ACLNN tensor view、binding 与 kernel 必须一起修改，防止中间层隐式转换并改变回写目标。

## 6. 所有权与读写不变量

每次执行前由框架/adapter 保证：

1. **读状态有效**：Conv 和 SSM 对应同一请求、同一已计算 token 边界。
2. **写集合独占**：不同活跃请求不能写到同一物理 state 区域；不同表项还需检查底层地址别名。
3. **共享快照只读**：prefix hit 可以重复读，必须获取框架已有的独占可写状态或 COW 后再写。
4. **避免跨请求读写冲突**：请求 A 的写集合不得覆盖 B 尚未读取的初始状态。write ID 唯一还不够。
5. **原位先读后写**：同请求 read/write alias 必须在任何覆盖前保存所有所需历史和初始 SSM；跨 owner 同步点也需审查。
6. **未触及状态不变**：sentinel 块、其他请求、页 padding 和未发布 prefix 不允许被修改。
7. **checkpoint 可选择**：每个实际写入 checkpoint 与相应输入前缀一致，拒绝后恢复正确；不能仅检查最终 H。
8. **生命周期一致**：释放、重用、抢占恢复及 connector 搬移不与未完成 kernel 并发冲突。

以上正常快路径依赖 metadata 生产端与框架不变量；详细值域/冲突校验可以在 CPU reference、已有 CPU metadata 或诊断模式执行。不要为每层验证全表增加同步读回。

## 7. Prefix Cache 的特别要求

GDN 当前 recurrent state 大小不随上下文逐 token 增长，但支持 prefix 复用仍需要保存离散 checkpoint；混合模型还要联合恢复普通注意力 KV。总缓存开销并不因此成为上下文无关常数。[H]

必须对齐：全注意力 KV、Conv 历史、SSM 状态代表相同的已计算前缀。不能将拒绝候选的临时 checkpoint 发布为有效 prefix。更晚的最终 SSM 不能通过缩短 seq\_len 还原更短前缀。

首版可将相关共享 prefix 场景回退；后续接入应复用现有分配与发布机制，不能单靠“Mega 支持独立 read/write slot”宣称完成 prefix 支持。cache mode（包括当轮可能存在的 none/all/align）、对齐边界与 copy 时机需本地重查；本文不将历史模式说明固定为今日 API。

## 8. Padding、空行与变长

原版 Mega 的合法索引从 0 开始；vLLM 的 `PAD_SLOT_ID`/`NULL_BLOCK_ID` 等哨兵不能直接用于解引用。不能将所有无效行 clamp 到 0，这会污染真实 cache。[V/D]

两条可选方案：

- **适配 kernel 的活跃行协议**：无效行不读取真实 state、不写真实 state；所有参与者仍按要求到达全局同步点。不能简单在 barrier 前对某些 owner `return`。
- **兼容原 ABI 的独占 sink**：每个 padding 行拥有合法独立写槽、足够长度的输入和初始状态，读写均不与真实请求冲突；图捕获前固定地址。sink 容量与计算成本计入资源/性能。

首版 eager 可以直接拒绝有 padding/变长的批次。图 replay 的资格与路由由图外已存在的模式选择机制保证；捕获时的 Python 条件不会每次 replay 自动重新执行。必须测试上轮 spec、此轮 no-spec、再下一轮 spec，清除失活行旧 metadata。

S 变化还涉及“上一轮 checkpoint 表宽”和“本轮校验长度”不相同的问题；原版 slot×S 不能随新 S 直接解释旧池。未解决前禁止动态 S 命中。

## 9. 数值契约：复用融合，不默认逐位等价

原版设计使用 Conv FP32 累加和 SiLU，再 BF16 物化；Q/K FP32 L2Norm；g/beta FP32 计算后 BF16 物化再读回；SSM FP32；readout BF16 后进入 RMSNorm/Z gate，最终 BF16。其 eps 为 1e-6，softplus threshold 为 20。[V]

**本次发现的具体差异**：基线 `DeviceOperator.fused_gdn_gating` 指向 `fused_gdn_gating_patch`，其 g 输出张量为 FP32，beta 输出为 b.dtype。原版 Mega 文档将 g 舍入至 BF16。原生 recurrent 接收 g；必须追至 kernel 实际算术，不能将差异仅视作名字不同。[V]

| 核对点 | 本地动作 | 服务器证据 |
| --- | --- | --- |
| g 是否 BF16 舍入 | 查实际分发和 producer/consumer dtype；原则上按 vLLM 保留 FP32 | 相同输入下 g、decay、第一处分歧的 H |
| Q/K L2Norm 的输出与 scale | 查 eps、输出 dtype、量化点、是否已含 `1/sqrt(D)` | q/k 及首 token readout；防止 scale 两次 |
| Conv | 权重方向、bias、激活、历史排列 | convOut 与更新后的原始 QKV 窗口 |
| RMSNorm / z gate | norm\_weight dtype/广播、eps、运算次序 | pre-norm、post-norm、最终输出 |
| SSM | dtype、矩阵方向、更新顺序 | 每个 token checkpoint，持续多轮误差 |

首版遇到非零/存在 Conv bias、不同激活/eps、不支持的 norm 权重布局、state dtype 或量化投影输出格式，均先回退；不要静默忽略参数。

需要两个相互独立的参考：原版算子测试验证“计算实现迁移没坏”；vLLM 原生链/独立顺序 reference 验证“适配后满足框架语义”。不能将两个 kernel 共用的错误地址 helper 当唯一 oracle。

容差在 P0/P2 根据基准 dtype、误差统计和下游行为确定。索引、token 边界、未触及内存和游标比较是精确比较；浮点同时报告 max abs、带分母下界的相对误差、RMSE、NaN/Inf。端到端接纳率可受微小数值扰动影响，须进一步核对 logits 和状态，不能只看生成文本。

## 10. 契约审查完成表

P0/P2 提交前逐项填入当轮 SHA 与证据位置：

- 每 rank 的实际 shape/dtype/stride 与权重布局。
- 四类数量分开：本轮 query length、草稿接受数、有效 state cursor、图 padding 行数。
- 采样至 metadata 的游标变换及 request/batch/group 映射。
- SSM 表行宽/flatten 编码与 Conv 历史偏移独立解释。
- 真实 cache storage\_offset/stride、64 位地址计算。
- alias、跨请求读写冲突、COW 和未触及区域保护。
- norm 恰好一次，数值差异已解释。
- launch 前 fallback；launch 后失败不复用污染状态。
- 连续两轮以上及 postprocess 重置游标用例通过。

未勾选项是待完成工作，不是允许默认假设为真的条件。
